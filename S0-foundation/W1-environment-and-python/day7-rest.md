## 7. 复盘问答

> 今天是休息和收尾。下面这些问题是关于“怎么休息、怎么总结、怎么进入下一周”的。

### Q1. 休息日真的完全不学吗？怎么休息才不影响节奏？

休息日的目标是**恢复**，不是“换一种方式学习”。可以做的事：

- 睡够。
- 散步/运动，离开屏幕。
- 轻量翻笔记 20-30 分钟，不做新题、不装环境、不看新框架。
- 把下周第一件事写下来，让大脑知道“已经安排好了”。

不建议：

- 打开 vLLM/PyTorch 教程“随便看看”——这会消耗注意力，又不形成产出。
- 熬夜补进度——下周一开始就欠睡眠，后面更难持续。
- 用“刷短视频”填满一天——不是真正的恢复。

工程视角：学习是长期项目，休息是**必要的维护窗口**，不是偷懒。

### Q2. 周总结怎么写才有用？怎么避免流水账？

只写四行，每行都要能行动：

```text
本周完成：列出有证据的交付物（文件/测试/commit）。
没达标：具体到哪一项、为什么。
最大卡点：现象 -> 已试方法 -> 最终原因。
W2 第一件事：具体到一个文件/一个命令。
```

避免：

- “这周很忙”“学了很多”——无法行动，也无法验证。
- 把“看了教程”当“完成”；验收看交付物。
- 列 10 个下周目标；只保留 1-3 个最重要的。

示例：

```text
本周完成：实验记录器可运行，23 个测试通过，GitHub 首次推送成功。
没达标：tmux 断线重连还没实测；W1 出口标准第 3 项需要再练。
最大卡点：相对导入报错；原因是直接运行 main.py，没有包上下文。
W2 第一件事：把 Experiment 改成 dataclass，并补类型标注。
```

### Q3. W1 没做完，W2 要不要等？怎么带着缺口进入 W2？

不要无限期等。按“影响面”分三类：

| 缺口 | 处理 |
|---|---|
| 影响 W2 重构（类、模块、异常、Git） | 先补，最多补 1-2 天 |
| 只影响熟练度（`@classmethod` 细节、复杂冲突） | 带着走，W2 遇到再补 |
| 属于加分项（pytest、类型标注、日志） | 直接留给 W2 |

具体做法：

1. 在周日 note 里写“W2 第一天补什么”。
2. W2 第一天先花 30-60 分钟补缺口，再开始新内容。
3. 不要把 W1 所有内容重学一遍；只补“不会就卡住”的部分。

工程原则：**先恢复可运行状态，再追求完整**。W1 的项目能跑、能测、能讲，比“每一条都完美”更重要。

### Q4. W2 的 dataclass、类型标注、日志、argparse 和 W1 项目怎么衔接？

W2 不换项目，直接在 `project/` 上重构：

| W2 主题 | 在 W1 项目里的落点 |
|---|---|
| dataclass | 简化 `Experiment.__init__/__repr__/__eq__` |
| 类型标注 | 给 `models/storage/service` 的函数加签名 |
| 日志 | 替换 CLI/service 里的 `print`，记录操作和异常 |
| argparse | 把菜单式 CLI 改成 `python main.py add/list/summary` |
| 装饰器 | 给 service 方法加计时/日志 |
| 上下文管理器 | 管理文件写入、临时目录 |
| 迭代器/生成器 | 流式读取实验记录 |

衔接方式：

1. 先保留 W1 测试，确保重构不改变行为。
2. 每引入一个特性，只改一个文件/一层。
3. 每次重构后跑测试；测试挂了先回退。

W2 的目标不是“用上所有新语法”，而是**让项目更好维护**。如果某个特性用不上，就不要硬塞。

### Q5. 怎么判断自己是“真的会了”，而不是“看懂了”？

三个自测：

1. **关掉教程重写**：从空白文件写一个最小版本；写不出来就是没会。
2. **预测输出**：看一段代码，先说出结果，再运行验证。
3. **讲给别人**：用“问题 → 方案 → 代价”讲清；对方能追问，你能答上。

更严格的标准：

- 能举出反例/边界。
- 能说出为什么不用另一种方案。
- 能在 10 分钟内定位一个类似 bug。

如果只是“看教程时觉得有道理”，那叫**熟悉**，不叫掌握。W1 的出口标准就是按“能独立做/能讲清”设计的。

### Q6. 下一周时间怎么排？课表/实习冲突怎么办？

排时间的原则：

- 先保**主任务 3 小时**，再排复盘；不要先排碎片时间。
- 每天只安排一个主线任务，不开新坑。
- 每周留 1 天补漏 + 1 天休息。
- 如果课表/实习冲突，**砍范围，不砍睡眠**。

具体做法：

```text
周一至周五：主任务 3h（固定时段，像上课一样）
周六：补漏/重跑实验 3h
周日：休息 + 周总结 30min
```

如果某天只能学 1 小时：

- 优先推进主任务的最小一步（例如写完一个函数）。
- 复盘压缩成 3 行。
- 不要把“没学够”变成熬夜的理由。

工程视角：可持续的节奏比短期冲刺更重要；W1 只是 6 周，后面还有 S1-S5。
